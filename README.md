# 传统技艺学徒成长与岗位衔接服务

大师工作室与技能学校共用一套只追加事实：课程目标、工艺能力、现场作品、导师观察各自保留来源；
能力由学校与工作室按当时规则共同确认；补充或撤回证据只产生新结论，不抹掉历史；
岗位班次只排能力满足（含食品安全硬门槛）且时间不冲突的人，条件变化时自动失效并重算。

## 运行

```bash
npm test
```

20 个端到端场景测试覆盖：多源互认、双机构确认、证据撤回留痕、规则 v1→v2 升级、
食品安全硬门槛、协作贡献、授权摘要隐私、时间冲突、导师停带/工坊暂停自动重算、门店追溯、命令幂等。

## 结构

```
src/
  ledger.js      只追加事件账本（命令幂等）
  catalog.js     能力目录与规则版本（rule-v1 / rule-v2）
  projection.js  事件流 → 当前状态
  service.js     领域服务：认定、联合确认、授权摘要、排班与自动重算、读模型
  ingest.js      既有工作室/课程记录纳入服务（可重复导入）
  seed.js        读取 fixtures/seed.json
fixtures/
  seed.json      工作室、课程、学徒、协作作品、评价、规则升级、授权、班次样例
docs/
  领域模型.md     原则、事件、不变量与场景对照
test/
  scenarios.test.js
```

## 一条上岗决定能追到什么

`GrowthService#onboarding(assignmentId)` 一次返回：
课程与阶段成绩 → 现场作品与本人贡献 → 能力结论与规则版本 → 学校/工作室确认者 →
食品安全凭证 → 仍缺训练；决定失效时同时给出失效原因与替代安排。
